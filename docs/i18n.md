# Translating an app

[Documentation](README.md) · [Project README](../README.md)

`ui.Strings` words the controls' own text: a dialog's "Close", a pager's
"Next". Package `i18n` (`github.com/ironpark/ggui/i18n`) translates the rest,
the app's own text, the same way: the translations travel down the tree in the
Env, and a message is a value translated when it is read during layout. A
language change lays the affected text out again and rebuilds nothing, two
subtrees can show two languages at once, and there is no global "current
language".

## Quick start

```go
var ko = &i18n.Catalog{
	Lang: "ko",
	Messages: map[string]string{
		"New sandbox": "새 샌드박스",
		"Delete %s?":  "%s{을/를} 삭제할까요?",
	},
	Plurals: map[string]i18n.Forms{
		"%d sandbox running": {Other: "샌드박스 %d개 실행 중"},
	},
}

lang := ggui.State("en")
loc := i18n.New(lang, ko, ja)

app := ggui.New(ggui.Config{Title: "Sandboxes"}, func() ggui.Widget {
	return i18n.Provide(loc, widget.Column(
		widget.TextOf(i18n.T("New sandbox")),
		widget.TextOf(i18n.N(len(sandboxes), "%d sandbox running", "%d sandboxes running")),
		ui.Button("한국어", func() { lang.Set("ko") }),
	))
})
```

The key of a message is its sentence in the source language, English here. A
sentence no catalog translates is shown as written, its arguments filled in,
so an app works before any translation exists and a missing one shows English
rather than a key.

`i18n.Provide` puts the Localizer in the Env of a subtree, together with the
language (`ggui.LanguageKey`, which text is shaped by) and its direction
(`ggui.DirectionKey`, chosen with `i18n.Direction(tag)`: right to left for
Arabic, Hebrew, Persian, Urdu …; see [Right-to-left text](fonts.md#right-to-left-text)).
All three follow `lang`: `lang.Set("ko")` lays the tree out again in Korean,
and the builder does not run.

A language is looked up as its tag, then with its subtags dropped one by one
("pt-BR", then "pt"), then the source. Tags compare without regard to case or
to `_` and `-`.

## Messages are values

`i18n.T` and `i18n.N` return an `i18n.Message`, not a string. A Message is a
`ggui.Readable[string]`, so every widget that follows a reader takes one, with
no API of its own: `widget.TextOf(m)`, `BindContent(m)`, `BindName(m)` and any
other `Bind` setter. Its `Get` translates it with the Localizer of the Env it
is read in:

- read while a widget lays out or paints it, the Env of the subtree it is in,
  the one an `i18n.Provide` above it gave. That covers accessible names, which
  a control reads as it paints, and the content of popups, dialogs and
  tooltips, which see the Env of the subtree that opened them;
- read anywhere else (a builder, an Effect, a callback, a menu), the
  application's environment: see [Install](#off-the-tree).

That is `ggui.CurrentEnv`, which any reader of your own can call too. A widget
of your own that has an Env at hand translates with `m.In(env)` in `Layout`,
or `i18n.From(env).S("…")`. `m.String()` is the source language, as written.

Arguments are formatted as `fmt.Sprintf` formats them. One that is itself a
Message, or any `ggui.Readable[string]`, is resolved first, in the same
language; one with a `GetAny` method, as a `*ggui.StateValue` has, is read:

```go
i18n.T("Moved to %s", i18n.T("Trash"))
i18n.T("Delete %s?", name) // name a string, or a *ggui.StateValue[string]
```

A message with no arguments is shown exactly as written, so a `%` in it is
written once. Two Messages without arguments compare equal when their text
and context do, so a rebuilt tree that hands a widget the same message again
changes nothing.

Controls of `ui` that take their label as a plain `string` (a `ui.Button`, a
`ui.MenuItem`, a `ui.Tab` …) take it once. Build those with the label a
widget instead where the control allows it, and name it with the message:

```go
ui.ButtonOf(widget.TextOf(i18n.T("Save")), save).BindName(i18n.T("Save"))
```

or rebuild them in a builder that reads `loc.S("Save")`.

## Off the tree

Text that is not a widget does not lay out: a menu bar, a tray, a window
title, a notification. Two tools cover it.

`i18n.Install(loc)` makes `loc` the application's Localizer: it puts it, its
language and the direction in the application environment (`ggui.SetEnv`) and
keeps them in step with the language. A Message read off the tree is then
translated by it, and so is any tree no `Provide` covers. An app in one
language at a time calls Install and needs no Provide:

```go
app.Setup(func() { i18n.Install(loc) })
```

`i18n.Watch(loc, fn)` runs `fn` now and again whenever the language changes,
for what takes strings and has to be set again: build them with `loc.S` and
`loc.N`, which translate now.

```go
stop := i18n.Watch(loc, func(loc *i18n.Localizer) {
	app.SetMenu(
		ggui.Menu(loc.S("File"),
			ggui.MenuAction(loc.S("New sandbox"), "cmd+n", create),
			ggui.MenuAction(loc.S("Quit"), "cmd+q", app.Quit),
		),
	)
})
```

`loc.S` and `loc.N` read the language, so a builder or an Effect calling them
runs again when it changes. Inside the tree prefer a Message, which needs no
rebuild.

## Plurals, context and Korean particles

**Plurals.** `i18n.N(n, one, other, args...)` takes the source sentence for a
count of one and for any other count. `n` picks the form and is also the first
format argument, so the sentences start with it; `args` follow. A catalog
translates it under the singular sentence with the forms of its language's
[CLDR plural categories](https://cldr.unicode.org/index/cldr-spec/plural-rules):

```go
Plurals: map[string]i18n.Forms{
	"%d file": {One: "%d файл", Few: "%d файла", Many: "%d файлов"}, // ru
}
```

The rules for whole numbers are built in for English, German, Dutch, Swedish,
Danish, Norwegian, Finnish, Italian, Spanish, Portuguese, French, Korean,
Japanese, Chinese, Vietnamese, Thai, Indonesian, Turkish, Russian, Ukrainian,
Polish, Czech, Slovak, Arabic, Hebrew and a few more; another language has
Other alone. A form left empty falls back to Other, and a plural no catalog
has to the source sentences, by `n == 1`. A form may leave the count out
(`One: "a file"`).

**Context.** The same English can need two translations: "Open" the verb on a
button and "Open" the state of an issue. `i18n.T("Open").Context("verb")` is
looked up under `"Open [verb]"`, and under `"Open"` when that is missing.

**Korean particles.** A particle such as 을/를 depends on whether the word
before it ends in a consonant. In a Korean catalog, a format verb directly
followed by the pair in braces gets the form that fits what the verb
formatted, so a translation need not write "을(를)":

```go
"Delete %s?": "%s{을/를} 삭제할까요?", // 사과를, 수박을
"Moved to %s": "%s{으로/로} 옮겼습니다", // 서울로, 부산으로
```

The first form goes after a final consonant and the second after a vowel;
은/는, 이/가, 과/와 and 으로/로 work alike, and 으로 also takes 로 after ㄹ. A
number is read as Korean reads it ("3" 삼, "10" 십); a word ending in anything
else, a Latin name say, takes the second form. It applies only to a
translation found in a Korean catalog. `i18n.Josa(word, withFinal, without)`
picks a particle in code.

## Dates, numbers and sizes

These are Messages too, written as the language writes them:

| Message | English | Korean |
| --- | --- | --- |
| `i18n.Since(t)` | 5 days ago, in 2 hours, just now | 5일 전, 2시간 후, 방금 |
| `i18n.Bytes(n)` | 512 bytes, 1.5 KB, 23 MB | 512바이트, 1.5 KB |
| `i18n.Number(n)` | 1,234,567.5 | 1,234,567.5 |
| `i18n.Date(t, i18n.DateShort)` | 11/18/2026 | 2026. 11. 18. |
| `i18n.Date(t, i18n.DateMedium)` | Nov 18, 2026 | 2026년 11월 18일 |
| `i18n.Date(t, i18n.DateLong)` | Wednesday, November 18, 2026 | 2026년 11월 18일 수요일 |

`Since` is measured when it is read, at layout. Nothing lays it out again as
time passes: a list of "5 minutes ago" refreshes with a state of its own that
changes every minute or so. `Bytes` counts in units of 1000, as the Finder and
most file managers do.

English and Korean are built in. Another language words them in its catalog,
under keys that are the English they replace; what it leaves out stays
English:

| What | Where | Keys |
| --- | --- | --- |
| Since | Messages | `just now` |
| Since | Plurals | `%d minute ago`, `%d hour ago`, `%d day ago`, `%d week ago`, `%d month ago`, `%d year ago`, and `in %d minute` … `in %d year` |
| Bytes | Plurals | `%d byte` |
| Bytes | Messages | `%s KB`, `%s MB`, `%s GB`, `%s TB`, `%s PB`, `%s EB` |
| Number | Messages | `. [decimal separator]`, `, [group separator]` |
| Date | Messages | the layouts `1/2/2006`, `Jan 2, 2006`, `Monday, January 2, 2006` (a `time.Time.Format` layout) |
| Date | Messages | `January [month]` … `Jan [month]` …, `Monday [weekday]` … `Mon [weekday]` … |

```go
var de = &i18n.Catalog{Lang: "de", Messages: map[string]string{
	". [decimal separator]": ",",
	", [group separator]":   ".",
	"Jan 2, 2006":           "2. Jan 2006",
	"Nov [month]":           "Nov.",
}, Plurals: map[string]i18n.Forms{
	"%d day ago": {One: "vor %d Tag", Other: "vor %d Tagen"},
}}
```

## Catalogs

A catalog is a Go value or JSON of the same shape. In Go:

```go
var ko = &i18n.Catalog{
	Lang: "ko",
	Messages: map[string]string{
		"New sandbox":    "새 샌드박스",
		"Open [verb]":    "열기",
		"%[1]s of %[2]s": "%[2]s의 %[1]s",
	},
	Plurals: map[string]i18n.Forms{
		"%d sandbox running": {Other: "샌드박스 %d개 실행 중"},
	},
}
```

As JSON, embedded and read with `i18n.Parse`:

```json
{
  "lang": "ko",
  "messages": {"New sandbox": "새 샌드박스", "Open [verb]": "열기"},
  "plurals": {"%d sandbox running": {"other": "샌드박스 %d개 실행 중"}}
}
```

```go
//go:embed locales/*.json
var locales embed.FS

func catalogs() []*i18n.Catalog {
	files, _ := fs.Glob(locales, "locales/*.json")
	var out []*i18n.Catalog
	for _, f := range files {
		data, _ := locales.ReadFile(f)
		c, err := i18n.Parse(data)
		if err != nil {
			log.Fatalf("%s: %v", f, err)
		}
		out = append(out, c)
	}
	return out
}
```

A translation is a `fmt` format with the arguments of its source sentence; an
explicit index such as `%[2]s` reorders them. The plural forms are `zero`,
`one`, `two`, `few`, `many` and `other`. `i18n.New` copies the catalogs it is
given and merges those of one language, a later one's translations winning.

## The system language

`i18n.Match(supported, preferred)` picks the tag of `supported` that best
serves a list of preferences: for the first preference any supported tag
serves, the same tag, else one with subtags dropped ("pt" for "pt-BR"), else
one of the same language ("en-US" for "en-GB"); the first supported tag when
none does. With the user's languages from `ggui.SystemLanguages()`:

```go
lang := ggui.State(i18n.Match([]string{"en", "ko", "ja"}, ggui.SystemLanguages()))
loc := i18n.New(lang, ko, ja)
```

`lang` is an ordinary state: a settings screen sets it, and the app follows.

## With ui.Strings

`ui.Strings` stay the controls' words and `i18n` the app's; `i18n` does not
know `ui`. Drive both from the one language:

```go
func stringsFor(lang string) ui.Strings {
	switch lang {
	case "ko":
		return koStrings
	}
	return ui.DefaultStrings()
}

root := ui.BindStrings(ggui.Map(lang, stringsFor), i18n.Provide(loc, app))
```

## Tooling

The `ggui` command keeps catalogs in step with the code. `ggui i18n extract`
collects the literal sentences of `i18n.T`, `i18n.N`, `.Context` and a
Localizer's `S` and `N` calls into catalogs, Go or JSON; `ggui i18n check`
reports the keys a catalog is missing and translations whose format verbs do
not match their source sentence's. See [the ggui command](cli.md#ggui-i18n).

### Your own helper functions

An app often wraps the package in helpers of its own, to keep call sites
short or to reach the Localizer it was handed:

```go
func tr(key string, args ...any) string { return loc.S(key, args...) }
func trn(n int, one, other string, args ...any) string { return loc.N(n, one, other, args...) }

label := tr("Delete %s?", name)
```

`ggui i18n` cannot tell that `tr` translates, so name it, in `ggui.toml`
or with `--func` and `--plural`:

```toml
[i18n]
funcs = ["tr", "ui.T"]  # like i18n.T; "say:1" when the message is the second argument
plurals = ["trn"]       # like i18n.N; "count:0,1" when the forms are not after the count
```

Then `tr("Delete %s?", name)`, `m.tr("Open").Context("verb")` and
`trn(n, "%d file", "%d files")` are read as `i18n.T` and `i18n.N` calls
are, in any file; `ui.T` matches `T` called through an import of a package
named `ui`, under any alias. A message may be a string literal or a string
constant of the same package (`const deleteMsg = "Delete %s?"`). The
helper's own body, which passes its `key` parameter on, is not reported as
a message that cannot be extracted. The source is read without types, so a
method is named by its name alone and `tr` matches a method called `tr` of
any type. See [Your own functions](cli.md#your-own-functions) for the full
rules.
